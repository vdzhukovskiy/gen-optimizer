# Региональные сценарии и измерение времени

Для первого запуска с чистой копии проекта: [пользовательская инструкция](../README.md).

## Запуск сценария с настройками

```bash
./build/Debug/gen-optimizer --scenario experiments/scenarios.json norway_coast
./build/Debug/gen-optimizer --scenario experiments/scenarios.json central_europe_rivers
./build/Debug/gen-optimizer --scenario experiments/scenarios.json finland_lakes
```

В окне также есть **Open scenario…**: выберите JSON и идентификатор сценария.
Имя отображается в Data и сводке результата. Загрузка не запускает расчёт:
нужно нажать Generate/G. При смене алгоритма и Reset используются настройки
выбранного сценария, включая его начальные значения.

Каждая запись содержит `data_file` (относительно папки JSON), `target_epsg`,
`default_algorithm` и `algorithms`. Например:

```json
"douglas-peucker": {
  "epsilon": {
    "min": 1,
    "max": 10000,
    "step": 1,
    "initial": 1000,
    "logarithmic": true
  }
}
```

`step` — шаг спинбокса в единицах параметра; логарифмический слайдер работает
непрерывно относительно этой настройки. Сетка автоматических прогонов пока
не реализована. Диапазоны текущих регионов пилотные: для Финляндии линейный
верхний предел 5000 м и начальное значение 500 м, для двух других сценариев —
10000 и 1000 м. Эти значения требуется обосновать предварительными прогонами.

JSON проверяется до изменения сессии: обязательные поля, имена алгоритмов и
параметров, конечные числа, границы, шаг, initial и положительный минимум
логарифмического диапазона. Неизвестные поля внутри параметра отвергаются.
До загрузки проверяется соответствие CRS данных `target_epsg`.
Если алгоритм не перечислен в `algorithms`, используются запасные диапазоны;
начальный алгоритм обязательно должен быть перечислен.

Обычный запуск с `.gpkg`/`.shp` остаётся доступным и не применяет настройки JSON.
Обычная загрузка после сценария снимает его настройки. Это различие намеренно:
для воспроизводимого эксперимента запускайте именно сценарий.
Активный путь конфигурации и её SHA-256 сохранены в Session для будущего журнала.
Манифест `.gpkg` описывает конфигурацию на момент подготовки данных, а текущий
JSON — настройки запуска: изменение параметров не требует перепроецирования
и не перезаписывает старый манифест.

Сценарии в `scenarios.json` задают источник, WGS84-границы участка
`[min_lon, min_lat, max_lon, max_lat]`, тип геометрии и целевую CRS.
Это начальные региональные наборы для проверки стенда; они ещё не представляют
полную выборку для итоговых выводов ВКР.

| Сценарий | Исходный слой Natural Earth | Участок | CRS |
|---|---|---|---|
| `norway_coast` | `ne_10m_coastline` | 6–9°E, 58–61°N | EPSG:32632, UTM 32N |
| `central_europe_rivers` | `ne_10m_rivers_lake_centerlines` | 8–12°E, 48–51°N | EPSG:32632, UTM 32N |
| `finland_lakes` | `ne_10m_lakes` | 24–30°E, 60–64°N | EPSG:32635, UTM 35N |

Участки находятся внутри области применения своих UTM-зон. Координаты,
H, Avg, epsilon и window_size выражены в метрах, area_threshold — в м².
Проекция всё равно имеет искажения; для других регионов CRS выбирают отдельно.
Дублирующий слой рек `scale_rank` в сценарии не включён.

## Подготовка

Используются уже имеющиеся GDAL и Qt Core; GDAL CLI/Python не требуются.
Исходные шейпфайлы вместе с `.shx`, `.dbf`, `.prj` должны находиться в одной папке.

```bash
cmake -S . -B build/Debug -DGEN_OPTIMIZER_BUILD_TESTS=ON
cmake --build build/Debug -j2
./build/Debug/tools/prepare-scenarios experiments/scenarios.json \
  ~/work/data/10m_physical experiments/generated/regions
```

Утилита обрезает геометрию по WGS84-прямоугольнику и затем перепроецирует её.
Линии сохраняются как MultiLineString, полигоны как MultiPolygon: обрезка может
разбить одну исходную фичу на несколько частей. Атрибуты сохраняются;
`source_fid` указывает исходный FID. Касания границы меньшей размерности
отбрасываются и подсчитываются. Ошибка геометрии или преобразования прерывает
подготовку, а не заменяет проблемную геометрию незаметно.

Получаются отдельные `.gpkg` и `.manifest.json`. Манифест фиксирует конфигурацию,
контрольные суммы исходных компонентов и результата, GDAL-версию, CRS,
границы результата, число фич/вершин и количество обрезанных фич.
Контрольная сумма идентифицирует конкретный файл: служебные даты GeoPackage
могут различаться между повторными подготовками.

Готовые данные в `generated/` игнорируются Git. Существующие результаты
утилита не перезаписывает: для нового прогона укажите другую выходную папку.
При ошибке может остаться неполный GeoPackage без манифеста; для повторного
запуска также используйте новую папку. Каждый сценарий загружайте отдельным
файлом, поскольку все три файла в одной папке имеют разные или независимые CRS.

```bash
./build/Debug/gen-optimizer experiments/generated/regions/norway_coast.gpkg
./build/Debug/gen-optimizer experiments/generated/regions/central_europe_rivers.gpkg
./build/Debug/gen-optimizer experiments/generated/regions/finland_lakes.gpkg
```

Генерализация по-прежнему запускается только по Generate/G.
При обычной загрузке файла стартовые значения в манифесте не применяются автоматически:
DP epsilon=1000 м, VW area_threshold=100000 м², Li–Openshaw window_size=1000 м.
Это примеры для исследования чувствительности, а не оптимальные настройки.
Без сценария для метрических данных Session предлагает линейные диапазоны 1–10000 м
и диапазоны площади 1–100000000 м². При смене диапазона настройки сбрасываются.
Для географических данных прежние диапазоны сохраняются. Диапазоны в метрах
не получены пересчётом градусов и требуют уточнения по результатам экспериментов.

Обрезка создаёт новые концы линий и границы полигонов: сравниваются оригинал
сценария (уже обрезанный и спроецированный) и его генерализация. Эффекты границы
участка учитывайте при выборе визуальных примеров и интерпретации результатов.
Natural Earth 10m — генерализованный набор, поэтому выводы относятся к этому
уровню исходных данных, а не к геометрии максимальной детализации.

## Времена

- `Gen ms`: подготовка выходных фич, резервирование памяти, копирование атрибутов,
  упрощение и обновления прогресса внутри этого этапа.
- `Eval ms`: функция оценки качества, включая проверки вырожденности,
  счётчики, расстояния и её обновления прогресса.
- `Layer ms`: полный расчёт слоя, включая накладные расходы между этапами.
- `calculation` в сводке: полный `GeneralizationWorker::run` для всех слоёв,
  включая создание алгоритма и подготовку контейнеров. Это не сумма округлённых
  значений таблицы и не длительность от нажатия кнопки до перерисовки окна.

Времена измеряются монотонным QElapsedTimer в рабочем потоке. Загрузка,
подготовка сценария, запуск потока, доставка результата в GUI, построение
QPainterPath и рендеринг в эти времена не входят. При отмене предыдущие
завершённые времена сохраняются вместе с предыдущим результатом.
Чистая функция `metrics::evaluate` сама время не измеряет: временные поля
Eval/Layer заполняет worker. При независимом вызове evaluate они равны нулю.

Для сравнений используйте одинаковую сборку (обычно Release), данные,
настройки оценки и число повторений. Отдельный прогон не оценивает разброс;
сохраняйте несколько запусков и сравнивайте медианы.

Основа преобразований: [GDAL OSR tutorial](https://gdal.org/en/stable/tutorials/osr_api_tut.html).
Порядок осей явно задан как longitude/latitude → easting/northing.

## Режимы оценки расстояний

В панели алгоритма `Metric evaluation` выбирает `Fast` (каждая N-я вершина,
по умолчанию N=8) или `Detailed` (каждая вершина, N=1). Оба конца линии
проверяются всегда. `Sampling step` задаёт N от 1 до 1000000 только для Fast;
при переходе в Detailed выбранный шаг Fast запоминается. Для коротких линий
или большого N быстрая оценка может ограничиться концами и пропустить изгибы.

Настройки фиксируются при Generate/G и при заявке Restart. Изменение настроек
не запускает расчёт; Cancel сохраняет предыдущий готовый результат вместе
с его режимом. В сводке отображаются режим и фактический шаг результата,
в подсказках H/Avg — шаг оценки. Настройки оценки не меняют упрощённую геометрию,
число вершин и счётчики пригодности, но могут менять H, Avg и время Eval.
Подробный H не меньше быстрого при одинаковых геометриях; для Avg такого
правила нет, поскольку меняется выборка усреднения.

В `GeneralizationResult` сохраняется `EvaluationSettings`, в метриках слоя —
`sample_stride`. Настройки действуют в текущей сессии; конфигурация сценария
пока их не содержит. Журнал завершённых прогонов и экспорт CSV описаны ниже. Оба режима остаются
приближёнными оценками по вершинам до сегментов, без гарантии точного непрерывного
расстояния Хаусдорфа. Исключение вырожденных/несопоставимых фич одинаково.

## Журнал прогонов и CSV

После каждого успешного расчёта Session добавляет неизменный снимок настроек
и метрик в журнал. Повторный запуск с теми же настройками имеет новый UUID.
Run history… показывает журнал и обновляется при завершении задач. Загрузка
другого файла/сценария сохраняет прежние записи. Отмена, ошибка и отброшенный
результат после смены данных не создают запись.

Export CSV… сохраняет весь журнал в выбранный файл в рабочем потоке. Снимок
журнала берётся при выборе файла; новые завершённые прогоны войдут в следующий
экспорт. Запись через QSaveFile атомарно заменяет файл, без дописывания; при
ошибке приложение сообщает о ней. Журнал хранится в памяти: перед закрытием
нужен явный экспорт. Автосохранения, импорта журнала и хранения геометрий нет.

Формат версии 1: UTF-8 без BOM, разделитель запятая, десятичная точка,
перенос строк CRLF. Кавычки, запятые и переносы внутри значений экранируются
по правилам CSV. Для открытия в табличном редакторе явно выберите эти настройки.
Одна строка = один слой одного прогона. Названия полей:

| Поля | Смысл |
| --- | --- |
| schema_version, run_id | Версия формата и UUID прогона; один UUID повторяется для всех его слоёв. |
| started_utc, finished_utc | Время начала задачи и принятия готового результата в GUI, UTC с миллисекундами. Это не границы замера calculation_ms. |
| data_path, layer_filter | Абсолютный путь загруженных данных и фильтр обычной загрузки. |
| scenario_id, config_path, config_sha256 | Имя сценария, путь и SHA-256 JSON, зафиксированного при загрузке. Пустые при обычной загрузке. |
| algorithm, parameters_json | Имя алгоритма и компактный JSON параметров снимка запуска. |
| evaluation_mode, sample_stride | fast/detailed и фактический шаг оценки. |
| layer_index, layer, crs_epsg, crs_units, crs_wkt | Индекс слоя с нуля, имя и координатная основа именно этого слоя. EPSG=0 означает неизвестный код. |
| orig_vertices, result_vertices, compression_ratio | Вершины оригинала/результата и доля оставшихся вершин. |
| orig_features, surviving_features | Число исходных и невырожденных результирующих фич. |
| evaluated_features, invalid_comparisons | Учтённые и исключённые пары фич для расстояний. |
| orig_degenerate_features, degenerate_features | Вырожденные фичи исходника и результата. |
| hausdorff, average_deviation | Приближённые отклонения на учтённом подмножестве в crs_units. NaN/Infinity — пустая ячейка, настоящий ноль — 0. |
| simplification_ms, metrics_ms, layer_ms | Время подготовки/упрощения, оценки и всего слоя. |
| calculation_ms | Полное время worker для всего прогона; повторяется в каждой строке его слоёв. Не суммировать по слоям. |

При анализе группируйте строки по run_id. Не сравнивайте расстояния с разными
CRS, режимами оценки или покрытиями без учёта этих различий. Значения записываются
с точностью для обратного чтения double, без округления до точности UI.
Манифест подготовки остаётся отдельным документом: его содержимое и контрольная
сумма самого датасета в CSV автоматически не копируются. Путь и SHA-256 JSON
не заменяют сохранение исходных/подготовленных данных и манифеста эксперимента.
