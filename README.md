# gen-optimizer: как начать работу

Программа сравнивает алгоритмы упрощения картографической геометрии.
Для первых экспериментов рекомендуется запускать подготовленные региональные
сценарии: там координаты в метрах и явно заданы диапазоны параметров.

Путь данных:

```text
Исходный Natural Earth + scenarios.json
                 ↓ prepare-scenarios (один раз)
     Региональные .gpkg + .manifest.json
                 ↓ приложение + тот же scenarios.json
       Выбор алгоритма и параметров → Generate → карта и метрики
```

**Что за файлы:**

| Файл | Зачем нужен |
|---|---|
| Исходные `.shp` и сопутствующие файлы | Данные Natural Earth в градусах. Хранятся отдельно от проекта. |
| `experiments/scenarios.json` | Рецепт подготовки регионов и настройки их запуска. |
| `experiments/generated/regions/*.gpkg` | Готовые обрезанные и спроецированные данные в метрах. |
| `*.manifest.json` | Запись о подготовке: источники, CRS, количество объектов и контрольные суммы. |

Манифест не является сценарием запуска: приложение читает `scenarios.json`
и выбранный `.gpkg`. Манифест нужен для проверки происхождения данных.
Готовые данные не хранятся в Git, поэтому после получения чистой копии проекта
их нужно подготовить или перенести вместе с манифестами с другого компьютера.

**1. Установить зависимости и собрать программу.**

Нужны компилятор C++20, CMake, Qt6 Widgets и GDAL/OGR с поддержкой PROJ,
GEOS и GeoPackage. На Ubuntu/Debian/Linux Mint пример установки:

```bash
sudo apt update
sudo apt install build-essential cmake qt6-base-dev libgdal-dev
```

Откройте терминал в корне полученной копии проекта, где лежит `CMakeLists.txt`:

```bash
cmake -S . -B build/Release -DCMAKE_BUILD_TYPE=Release -DGEN_OPTIMIZER_BUILD_TESTS=ON
cmake --build build/Release -j2
ctest --test-dir build/Release --output-on-failure
```

Получатся приложение `build/Release/gen-optimizer` и утилита
`build/Release/tools/prepare-scenarios`. Для сравнения времени используйте
одинаковую сборку; команды ниже рассчитаны на этот Release-каталог.
Python-модули GDAL и отдельная программа ogr2ogr не требуются.

**2. Скачать и распаковать исходные данные.**

На странице [Natural Earth — 1:10m Physical Vectors](https://www.naturalearthdata.com/downloads/10m-physical-vectors/)
скачайте весь комплект физических слоёв или отдельно Coastline,
Rivers + lake centerlines (обычный вариант) и Lakes + Reservoirs.
`10m` здесь означает масштаб 1:10 млн, а не точность 10 метров.

Распакуйте файлы, например в `~/work/data/10m_physical/`. В этой папке
непосредственно должны лежать:

```text
ne_10m_coastline.shp
ne_10m_rivers_lake_centerlines.shp
ne_10m_lakes.shp
```

Для каждого слоя оставьте рядом его `.shx`, `.dbf`, `.prj`, а также `.cpg`,
если он есть. Одного `.shp` недостаточно для надёжной загрузки всех сведений.
Если архив распаковался во вложенные папки, соберите компоненты этих трёх
слоёв в одну папку. В командах можно указать другой путь к исходным данным.

**3. Подготовить региональные файлы — один раз.**

В корне проекта выполните:

```bash
./build/Release/tools/prepare-scenarios experiments/scenarios.json \
  ~/work/data/10m_physical experiments/generated/regions
```

Утилита читает из JSON название исходного слоя, границы региона и целевую CRS,
обрезает геометрию и переводит координаты в метры. Исходные файлы не меняются.
Получатся по два файла для каждого региона:

```text
experiments/generated/regions/
  norway_coast.gpkg
  norway_coast.manifest.json
  central_europe_rivers.gpkg
  central_europe_rivers.manifest.json
  finland_lakes.gpkg
  finland_lakes.manifest.json
```

Если у вас уже есть эти подготовленные файлы для текущих границ и CRS,
повторять подготовку не нужно. Утилита не перезаписывает существующие результаты.

**4. Открыть сценарий в приложении.**

```bash
./build/Release/gen-optimizer --scenario experiments/scenarios.json norway_coast
```

Вместо `norway_coast` можно указать `central_europe_rivers` или `finland_lakes`.
Другой способ — запустить приложение без аргументов, нажать **Open scenario…**,
выбрать `experiments/scenarios.json`, затем нужное имя.

Приложение найдёт `.gpkg` по `data_file`, проверит CRS и применит алгоритм,
диапазоны и начальные значения из JSON. `data_file` считается относительно
папки JSON, а не текущей папки терминала. Поле **Scenario** показывает выбранное
имя; **CRS** — систему координат и единицы.

**5. Выбрать параметры и запустить расчёт.**

- Выберите алгоритм, настройте параметры и режим **Metric evaluation**.
  **Fast** проверяет каждую N-ю вершину (по умолчанию шаг 8), **Detailed** —
  каждую вершину. Концы линий включаются в обоих режимах. Нажмите **Generate**
  или **G**. Для быстрой настройки используйте Fast, для перепроверки — Detailed.
- После загрузки и изменения параметров расчёт сам не запускается.
- **Reset params** возвращает `initial` выбранного алгоритма из сценария.
- **Cancel** останавливает задачу, сохраняя предыдущий завершённый результат.
- Во время работы **Restart** запускает новые настройки после остановки старой задачи.
- **O** показывает оригинал, **S** — результат, **A** — наложение.
- Колесо мыши меняет масштаб, перетаскивание левой кнопкой перемещает карту.
  **Fit map / F** возвращает общий вид.

Оригинал в региональном сценарии — уже обрезанный и спроецированный `.gpkg`.
С ним сравнивается результат генерализации; глобальный исходный Natural Earth
в этот момент не загружается и не накладывается поверх региона.
Выбор в интерфейсе не записывается обратно в JSON автоматически.

Выбор режима не запускает расчёт. Во время работы можно менять настройки:
текущая задача использует снимок при запуске, Restart фиксирует новые настройки.
Reset params сбрасывает параметры алгоритма; режим оценки сохраняется.

**6. Посмотреть метрики и повторить эксперимент.**

В сводке указаны режим и шаг завершённого расчёта. При изменении настроек старые
метрики остаются на экране с пометкой о предыдущем результате. Оба режима
измеряют расстояния от выбранных вершин до сегментов, а не точное непрерывное
расстояние Хаусдорфа. Подробная оценка может занимать значительно больше времени.
Режим хранится в текущей сессии и результате; в JSON он пока не задаётся.

`ratio` показывает долю оставшихся вершин; H и Avg — отклонения в единицах CRS.
В региональных сценариях это метры. Смотрите также `Used / skipped` и
`Deg orig / res`: расстояния относятся только к пригодным учтённым фичам.
`N/A` означает отсутствие подходящих фич, а не нулевое отклонение.

`Gen ms` — подготовка результата и упрощение, `Eval ms` — оценка метрик,
`Layer ms` — весь расчёт слоя. `calculation` в сводке — весь расчёт всех слоёв
в worker. Загрузка данных и отрисовка в эти времена не входят.
Каждый успешно завершённый расчёт автоматически добавляется в журнал.
**Run history…** показывает отдельные прогоны, в том числе повторные с одинаковыми
настройками. Журнал сохраняется при смене сценария и данных.

Нажмите **Export CSV…**, выберите файл и дождитесь сообщения `CSV saved`.
Экспорт сохраняет весь журнал на момент нажатия: одна строка на слой каждого
прогона. Сохраняются сценарий, данные и CRS, алгоритм и параметры, режим оценки,
метрики и времена. Пропущенные расстояния записываются пустыми ячейками.
Файл можно открыть в таблицах или обработать скриптом: кодировка UTF-8,
разделитель — запятая, десятичный знак — точка.

Журнал живёт в памяти до закрытия приложения: **экспортируйте его перед выходом**.
Отменённые и ошибочные расчёты не добавляются. Экспорт заменяет выбранный CSV,
а не дописывает строки. Геометрии в журнале нет, открыть старый прогон из CSV
на карте пока нельзя. Оптимизатор ещё не реализован.

**Когда повторять подготовку, а когда достаточно перезагрузить сценарий:**

| Что изменено | Что сделать |
|---|---|
| Алгоритм или параметр в окне | Нажать Generate; подготовку не повторять. |
| `min`, `max`, `step`, `initial`, `logarithmic`, `default_algorithm` в JSON | Сохранить JSON и снова открыть сценарий. `.gpkg` остаётся прежним. |
| Исходные данные, `source_layer`, `bbox_wgs84`, `geometry` или `target_epsg` | Подготовить новые `.gpkg` и манифесты, затем открыть сценарий. |
| Положение готового файла | Исправить `data_file` в JSON и открыть сценарий. |

Для повторной подготовки используйте новую папку, например
`experiments/generated/regions_v2`. Затем исправьте `data_file` у сценариев
на `generated/regions_v2/ИМЯ.gpkg`. Не меняйте только `target_epsg` у старого
файла: это не перепроецирует данные, и приложение обнаружит несоответствие CRS.

**Можно работать и без сценариев.**

```bash
./build/Release/gen-optimizer ~/work/data/10m_physical/ne_10m_coastline.shp
```

В этом случае исходный Natural Earth остаётся в градусах и используются
запасные диапазоны программы. Прямая загрузка `.gpkg` также не применяет
настройки JSON, даже если рядом лежит манифест. Для воспроизводимого эксперимента
используйте `--scenario` или **Open scenario…**.
Не загружайте папку с обычным слоем рек и его `scale_rank`-вариантом вместе:
совпадающие исходные участки могут разойтись после независимой генерализации.

При ошибке «Output already exists» выберите новую выходную папку; при ошибке
загрузки сценария проверьте `data_file`, наличие `.gpkg` и его CRS.
При ошибке подготовки проверьте комплект исходного шейпфайла и выбранные
границы/проекцию. Неполный файл без манифеста не используйте как готовый сценарий.
